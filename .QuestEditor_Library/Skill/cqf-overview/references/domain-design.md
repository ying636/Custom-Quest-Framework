# CQF 领域系统设计

推荐把领域做成一套稳定的战场规则：每个领域拥有可辨认的视觉特征、独立的生命与规则，共同战场负责空间和人员往返。展开动画、领域材质和地图生命周期分别扩展。这样新增领域可以保持自己的表现，也能直接参加对抗。

领域特征可以完全由真实地形和建筑构成，通用平面材质不是必选项。本机已实现无 surface 的通用融合与对抗、预生成建筑布局、原建筑对象收起/恢复及动态接触带。后续扩展坚持每种领域只实现一次自身规则与资源，公共战场组合双方能力；不为每对领域单独编写玩法分支。

本文是后续架构与玩法的设计建议。已经实现的接口和验证范围见 [领域系统](domain-system.md)、[领域视觉](domain-visuals.md) 和 [领域对抗](domain-contest.md)。较大重构与新增玩法在确认方案后实施。

原地图展开特效的大小差异已单独处理：各自保留真实配置半径，完全包围时形成围绕小领域的侵蚀接触环。展开阶段可行动，闭合阶段才捕获锁定，详见领域视觉。内部战场以后可采用容纳双方的固定尺寸档位，并从真实接触处按血量目标逐步争夺；这是后续建议，当前仍使用已有固定战场和分区规则，本轮没有实施内部地图扩容或闭合领地分界。

## 玩家应感受到的行为

展开保留各领域自己的动作与动画。需要呈现领域特征时，调用该领域的通用平面材质：血海使用血海地形 Shader，基础领域使用灰白流淌。融合展示叠加双方实际材质，通过侵蚀遮罩表现接触与争夺，随后一起遮盖画面，进入共同战场。

地图大小始终固定。双领域按当前绝对血量比例推进中间的整条分割线，玩家能同时看到双方血条、领域特征与阵地变化。分割线移动不搬动人物，也不删除地图格子。一方主动取消或崩塌后，人物与尸体被困在对方领域，本方规则立即解除；最后一个领域结束才分别返回并回收休眠。当前已实现并保存 Trapped 状态，规则解除使用 Dissolved，实际返回使用 Returned。

外部领域建筑持续存在，提供攻击与反制入口。建筑受伤和领域内施术者受伤扣除同一份领域血量。基础领域与血海当前最大血量都为 100000；具体技能消耗、回血与崩塌惩罚由各自规则处理。

## 运行职责

| 层次 | 唯一职责 | 应持有的状态 |
| --- | --- | --- |
| 领域定义 | 声明这个领域是什么 | 模板、最大血量、规则类型、展开配置、通用平面、载体 |
| 领域实例 | 管理一次领域使用 | 身份、施术者、当前血量、规则对象、参与者、外部载体 |
| 共同战场 | 管理共享空间 | 物理 Map、实例集合、分区、地形快照、转移事务 |
| 地图管理器 | 管理地图资源 | 预生成、唤醒、回收、休眠、存读档登记 |
| 表现层 | 消费当前状态并绘制 | 展开、通用平面、转场、血条、声音的临时资源 |

继续使用唯一的 `GameComponent_MapManager`。长期建议让所有领域实例使用同一种纯状态对象，由地图组件持有。当前第二方通过同类型的显式构造实例独立保存，不登记为原版地图组件；宿主组件已密封，防止派生类型被原版自动登记后取代宿主。后续可把实例状态进一步移出地图组件类型，规则不拥有第二套血量或私有地图池。

表现层接收实例和战场的只读状态。特效完成通过明确的完成信号通知运行层；Shader 不决定输赢，特效对象被销毁也不能代替领域正常退场。

## 三种视觉资源

| 资源 | 用途 | 复用原则 |
| --- | --- | --- |
| 展开表现 | 施术动作、扩散、幕墙、闭合 | 保留领域个性，不由通用平面配置改写 |
| 通用平面 | 融合、区域展示、预览等领域特征展示 | 同一领域共享材质算法，世界与屏幕只适配坐标和遮罩 |
| 转场表现 | 遮盖、切图、揭幕 | 统一处理切图屏障，具体外观可替换 |

血海地形和血海通用平面共用同一份 Shader 算法，避免两套血海外观随更新分叉。通用接口提供时间、空间映射、形状、透明度、对手范围和侵蚀遮罩。世界平面遵守人物层级；屏幕平面直接由 UV 重建坐标，避免依赖 GUI 没有提供的世界插值。

融合中的侵蚀属于表现。对抗中的规则归属仍由清晰的几何边界决定。边缘可以有流动、泡沫、雾化和渗透，但不能让玩家看见的大片优势区与实际技能判定相反。

当前接触带限制在规则边界两侧各 1.6 格，局部叠加已配置的双方材质，无特效方保留真实场景；推进形成压力，受伤产生反冲。规则线与领地面积仍由同一血量比例计算。建筑按完整占地归属显隐；收起保留对象、受损和组件状态，位置被占则等待，已摧毁对象不会在本次对抗中复活。初始特殊组件的蓝图扩展与运行中对象的完整保存分开处理。

## 生命周期与转移

地图资源状态与领域使用状态分别管理。地图在生成、休眠、使用、回收之间切换；领域使用在准备、展开、遮盖、活动、退出、完成之间推进。生命周期保留一个权威状态，失败原因另存，减少多个布尔值形成不可能组合。

进入事务依次准备目的地图、记录来源及参与者、确认安全落点、绘制完整遮盖、提交转移、等待目的地图实际地形帧，再揭幕并释放锁定。返回使用相同的事务顺序。同步展开的一对领域共享一次切图屏障，双方一起进入，一起完成入场保护。

跨图移动前，容器与飞行载具通过统一的准备入口释放人物。已转移、待转移和已返回人员分别记录；重试只处理剩余项。每次事务带有游戏及领域实例身份，退出游戏后的延迟回调不能作用于下一局。

无安全目的地图时保留人物、领域和来源记录，并明确报告原因。地图生成失败、材质失败、镜头离开、施术中断和人物死亡分别处理；不以销毁剩余地图作为通用恢复手段。

## 双领域对抗

用户确认的进攻机制是主动占领：领域主连续在敌方领地待满 3 游戏秒，转化当前位置半径 2 格，并在成功夺得敌格时恢复 300 领域血量。保护区优先；转化保留到被对方夺回或本方结束。占领完成后脚下变成本方领地，原地不能反复触发。对抗系统用同一分区实现据点面积、建筑、技能和主场减伤，双方同时触发按距离解决重叠。此机制已经实现；没有加入此前讨论中的维持节点玩法。

本机当前实现已扩展为领地战：入场解锁后双方每秒同步损耗各自最大血量 0.5%，不触发受击反冲；施术者在本方实际领地先减伤 30%，再进入共享血量吸收。跨区技能在具体模组实现削弱，血海初版保留 70% 强度。自动腹地孔洞已取消，侵蚀改为主动占领地在敌方主领地内持续暴露 10 游戏秒后失守；己方主线到达或保护生效重置计时。区域保护优先于血量面积，其他地区补偿，保护面积超过配额时作为下限。

新增回血、特殊建筑、守区技能只接入 RestoreHealth、RegisterStructure 与 ProtectTerritory 等公共入口，具体技能名称、成本、冷却和效果仍需内容设计。技能建筑可选择失地收起或留在敌区，来源建筑被毁会解除其守区，领域结束统一清理；无需为每对领域增加适配分支。这些公共能力与具体玩法技能须区分，不能把接口完成报告成所有新技能已经完成。

第一方目标面积比例为 `H1 / (H1 + H2)`，其中 H 是当前绝对血量。双方归零直接共同退场。血量变化更新目标比例，分割线按游戏 tick 平滑追赶；暂停时规则边界停止移动，装饰流动可单独控制。

当前主线保持贯穿地图的直线，左右朝向在对抗开始时确定。回血可推进主线夺回面积，扣血会让出面积；腹地只保留主动占领和保护形成的区域，不自动随机开洞。领地规则和画面共享同一归属，失守同步切换地形、布局及技能判定。血海在自己的区域内保持填满，避免血量同时影响分区和内部收缩。

技能、生成物与持续效果通过同一个归属查询入口工作。是否允许在对方区域施法、已有生成物越线后如何处理，应由规则明确声明；不让每个技能自行猜测自己在哪一张地图。

后续若支持旋转分割线，必须按裁剪后实际面积求偏移，不能直接把宽度比例当作斜线位置。若扩展三方以上，应采用连续且无空洞的面积分区求解；先确定玩法与成本，再增加实例数量。当前双领域上限保持清楚、可预测。

## 人物与战利品

共同战场维护一份人员账本，记录每个人属于哪个实例、来自哪里、是否已转移及原征召状态。尸体沿用人物归属，携带物跟随人物。松散战利品当前保留到最后一方返回，避免本方领域解除时把另一方仍在使用的物品清走。滞留方继续保存自己的来源记录，不改写成胜方的来源。

领域临时授予的能力和效果记录授予来源，只撤销本次实例实际授予的部分。规则清理要可重复执行，不能误删人物原本拥有的同名能力。外部载体正常移除与被攻击摧毁使用不同路径，避免正常退出再次触发崩塌。

## 性能与恢复目标

空闲管理器不扫描休眠地图。活动规则按事件更新目标，边界只刷新跨线列及相邻绘制区块。矩形分区使用固定网格和变换矩阵，避免随边界移动重新生成三张网格。已经用专有地形绘制领域材质的规则不再叠加相同全图材质。

材质与屏幕资源按需要创建，由明确的拥有者释放；屏幕材质延迟到首次使用才创建。世界与屏幕共用算法，但保留适合各自管线的入口。高分辨率融合阶段优先缩减不可见计算和重复覆盖，再考虑可配置的精度档位。

待切图与待退出队列应复用缓存，等待完整遮盖的稳定阶段以零新增分配为目标。本机本轮检查已验证 256 次等待退出重试新增分配为 0；这项结果仅代表该等待路径，不代表整个游戏每帧零分配。

新格式存档保存实例、人员账本、几何边界、来源和地图池身份，不保存临时 GPU 对象。读档先恢复引用和合法性，再重建规则及表现。默认不做旧存档迁移；当前格式的完整游戏重载仍须独立验收。

## 实施优先级

1. 稳定当前双领域：独立通用平面、保留展开表现、可靠遮盖、连续边界、独立退场、休眠复用和资源释放。
2. 收敛实例与状态：统一首方和挑战方的数据结构，引入明确的转移事务及可重复清理，补齐各阶段存读档验证。
3. 扩展规则契约：统一区域判定、临时能力来源、特殊容器交接和领域 AI 接口。
4. 在上述基础稳定后，再评审多方对抗、旋转边界和其他玩法，避免把未确定的规则写进通用地图层。

验收需覆盖基础与血海的全部配对、同时展开、途中加入、取消、远距离独立展开、血量反复变化、双方同时耗尽、先后退出、建筑受伤、人员与尸体返回、地图复用，以及展开和对抗期间的保存与完整游戏重载。动画验收要检查真实画面，不能只检查转场计时与内部遮盖标记。
