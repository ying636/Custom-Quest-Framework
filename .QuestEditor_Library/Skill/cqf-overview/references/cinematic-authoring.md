# 实体本与地图演出制作

## 连续制作流程

在开发者模式的实际地图打开实体本，搜索实体模板或已收录的生成方案。模板可以创建生成方案，也可直接进入“在地图放置”：先配置数量、概率、触发时机及到达方式，再选择地图位置。

地图放置保存的是编辑用生成点，不会立即生成人物、写正式实体记录或执行生成事件。地图保存时收集该生成配置；受损、摧毁触发要求生成点与实际建筑同格。放置后的窗口可编辑此处配置、继续放置、加入演出演员或记录该成员的移动。

成员编号按同一来源在当前任务中的实际生成顺序计算，同一方案多次使用继续编号，不是单个放置点内的局部编号。未生成成员可以先编排；实际生成后系统登记对象。死亡和丢失的成员不能选用；离图、倒地状态分别显示，走位仍须满足运行时的地图与行动条件。

搜索、分类与详情保持一致，无结果时清空旧选择。切换生成类型保留兼容公共设置；若将移除已配置的专属字段，先列出内容并等待确认。编辑库中方案与编辑地图上的“此处配置”使用独立副本，不自动修改所有使用位置。基础 `PawnSpawnData` XML 导出保存 `way` 的运行类型及其字段，复制和收录不再丢失到达方式。

## 演出编辑

底部工具栏提供撤销、重做及独立项目设置。连续输入合并为一次修改；新增、删除、排序、演员和字幕等纯值修改进入历史。普通预览复用工作台，副本测试返回时转交纯值历史，避免保留旧游戏对象。

项目设置内管理命名地点，可改名、定位、复用及删除未使用的地点。正在被步骤引用的地点不能直接删除。名称和未使用地点保存在 `.cqfscene` 与草稿中；正式定义只保留使用到的运行绑定。地点仍依赖制作世界与地图标识，本次没有跨世界坐标转换。

草稿写入当前游戏配置目录的 `CQF_CinematicDrafts/*.cqfdraft`，按世界标识隔离，以 UTF-8 XML 原子替换。字幕未完成也可保存草稿；草稿不写正式定义。草稿仅含定义值、双语正文、任务 ID、地点及录制对象 ID，不保存 `Game`、`Map`、`Quest` 或 `Pawn` 对象。损坏草稿先复制为 `.recovery-*` 再重新保存；备份失败则停止覆盖并显式报错。

只有演员、命名地点、任务关联或项目设置的草稿也属于已有内容，新建和载入替换前均须确认。实体本列表只绘制滚动范围内的行；运行记录按来源与任务索引，读档后重建，保留死亡成员的编号空位。地点面板一次绘制共用一次引用扫描。

## 从 CQF 4.4 升级

保留旧数据库目标、原演员来源和进行中的演出状态；已执行动作不会因升级重新执行。没有实体本组件的旧档自动补建组件，并将旧全局唯一实体缓存中明确对应模板的 Pawn 纳入无任务范围，不改其任务归属，也不生成新 Pawn。无法证明生成来源的旧普通人物继续使用原数据库或录制绑定。已有实体本的存档不会再次自动导入缓存。

旧生成方案缺少来源标识时，下次保存世界会补齐；新生成记录沿用该身份。制作时仍须保存地图或收录生成方案，才能把来源标识写入相应内容文件；演出草稿不代替地图或实体配置的保存。

## 测试

“副本测试”菜单提供全部步骤或当前步骤，并区分排演人物与正式来源。排演人物用于制作验证；正式来源测试清除排演覆盖，按正式演员来源解析。当前步骤测试仅保留所选子树使用的角色与绑定，不执行整片跳过动作或发送整片结果信号。完整测试使用原生存档检查点，返回后恢复世界与编辑选择；嵌套失败保留最深步骤路径，返回时定位该步骤。

预览及测试前刷新当前项目字幕的内存翻译，撤销字幕后不会继续使用修改后的旧正文。这不会把未完成草稿发布为正式资源。

原生检查入口位于 `Tests/EntityBookRuntime/RunChecks.ps1` 和 `Tests/CinematicStudioRuntime/RunChecks.ps1`，传入绝对路径的候选主库和编辑器。实体本检查还应通过 `-DevtoolsRuntimeDirectory` 显式指定本机有效的 RimDevTools 运行目录；临时历史目录可能被清理。测试使用独立游戏副本与保存目录，不操作用户当前存档。源码编译、模型检查、Targeter 回调测试、原生 GUI 点击和截图验收须分别记录。

4.4 升级检查使用 `Tests/SaveCompatibilityRuntime/RunChecks.ps1`，另传入已发布的 `LegacyCoreAssembly` 与 `LegacyEditorAssembly`。脚本先以旧 DLL 生成完整存档，再由候选 DLL 读取并二次保存/加载；不以删除新 XML 字段的模拟档替代旧版本生产档。
