# CQF 领域对抗

本实现自 CQF 4.0 引入，自 5.0 使用专用战场与包围战线。当前工作区已扩展为每场最多八个领域名额：第一实例由原版登记的 MapComponent_Domain 持有，其余实例显式构造、独立保存，不加入 Map.components，由主实例转发生命周期。通过 Instances、FindDomainFor、DomainAt 查询各方，不再用 Challenger 枚举整场。每方独立拥有 Worker、施术者、参与者、血量、来源和外部载体；地图仍由唯一 GameComponent_MapManager 托管。血海适配属于独立的寂屋邪祭仓库。

## 专用战场与展开入口

对抗使用独立物理 Map。N 个活动领域的尺寸倍率为 0.75×sqrt(2/N)，宽、高分别取各方配置之和乘倍率并向上取整，y=1。同为 60×60 时，二至八方依次为 90、111、128、143、156、169、180 格。加入新领域或合并战场时，两轴均至少比原战场增加一格，并扩大到能容纳原场景完整平移的尺寸；超大领域后加入超小领域也不会缩小。退出不缩图。按实际尺寸休眠复用，不预生成所有领域组合；首次缺少尺寸缓存时仍需生成地图。

- 普通地图单独展开仍使用本领域的预生成地图、罩子和闭合演出。
- 领域内反展开保留准备期的地面蔓延，闭合后本方特征自然覆盖全屏；遮盖帧后才迁移首方实例、全部场内物件与人物，随后从新领域模板建立挑战者，等待目的地地形帧后揭幕。原图休眠，反展开不再次升罩，也不唤醒一张挑战方独立地图。
- 两方同步展开，或在已有外部载体附近展开，保留原世界融合演出和完整覆盖屏障，然后直接进入专用战场。进入时使用双方缓存的地形与建筑蓝图。
- 两个已活动的领域合并时，迁移双方现有规则对象、血量、参与者与原建筑对象；同一来源地图的双方按原来源位置对齐，避免两个施术者挤在同一个中心。地形、建筑和普通物件采用同一平移映射，不拉伸格子或建筑。空间不足时寻找不覆盖现有物件的完整落点，失败报告并回滚。不同来源地图分别保留自己的最终返回位置。
- 建筑先托管，人物容器先释放；记录普通物件的来源、朝向与 Lord。迁移失败时收回已在新图显示的布局，再恢复双方位置、实例绑定、保护和原建筑，允许重试。迁移提交后旧空图清理独立报错，不再反向恢复已重置的实例；切图仅选择仍在目标地图生成且未销毁的施术者。测试主动注入 ContestStarted 异常验证此路径。
- 尚有名额时允许继续反展开，也允许两个已有战场整体合并，总实例数不能超过八。已退场实例保留参与者与返回记录，本场名额不回收；只在扣血时排除已退场者。场内仍有活动领域就继续困住所有生物，最后一个结束才统一返回并休眠。

### 多方领地与迁移

三至八方通过 DomainMultiTerritory 的加权不规则场分配领地，目标比例为各方当前绝对血量除以总血量。循环求解面积阈值，避免开战位置很近甚至相同时少数领域吞掉全图；弱方面积降低时增加向固定开战位置收拢的约束，形成内部孤岛。二方继续使用原曲线包围算法。保护、主动占领、地形、建筑显隐和技能归属均使用带实例索引的同一分区。

扩图在完整遮盖后迁移全部实例、原建筑、普通物件、领地覆盖和计时，随后揭幕。迁移期间仍在施法的其他展开物也随地图移动并恢复其闭合锁，避免同时反展开时丢失后完成的一方。Worker.MapTransferred(previous, offset) 用于子 Mod 平移自身持久坐标；特殊 Thing 可实现 IDomainMapTransfer。原版 Projectile 和 Mote 的轨迹/精确位置随平移更新。迁移失败恢复原场景并报告；提交后清理失败独立报告。

普通领域预加载顺带准备同尺寸对抗所需的战场，新增尺寸组合在实际需要时准备；首次未缓存尺寸仍可能生成，不能承诺任意组合都无首次等待。资源准备在播放转场前完成，演出时钟从实际可见首帧开始。GetMaps 拒绝空定义，防止缺失 Def 被误当成所有没有挑战者的地图；获取独立领域和模板时显式排除专用战场。

preload=true 的领域在准备阶段保留两张原类型地图，缓存原始 DomainMapTemplate（地形与建筑蓝图）并深度保存。反展开直接读取缓存，不再 Acquire / Activate 一张临时模板地图；同步展开只唤醒专用战场，双方均读取缓存。同类领域不再因唯一模板被自己占用而现场生成地图。同步展开唤醒按尺寸准备的专用战场，双方原类型地图继续休眠。缓存缺失或池容量耗尽的回退仍会生成地图，不能宣称无限次并发都不加载；正常两方对抗由预生成与缓存覆盖。

缺少模板或可用地图的回退先在加载事件中完成准备，结束后将仍有效的展开重新排队；`CompleteOpening` 不在加载事件中执行。所有转场的计时从实际地图重绘首帧开始，加载等待和演出许可排队不消耗特效时长。测试入口 `-cqfcounterrepair` 安装观察器，`-cqfcounterrepairdelay` 额外延迟首次可见帧；均只存在于临时测试程序集。

`DomainDef.surface` 可省略。纯建筑与地形领域使用原场景，公共绘制器只提供接触与转场遮盖，不创建整图颜色面。通用展开的 SupportsFusion 与 surface 解耦；自定义展开器仍需明确启用融合，Worker 仍需明确 SupportsContests。新增领域只提供自身定义、地图生成、规则和可选材质，不增加两两配对实现。

## 占地

`DomainTerritoryPartition.CalculateFraction` 使用当前绝对血量，第一方目标总面积比例为 `H1 / (H1 + H2)`，双方归零时为零。3000 对 1000 对应 75% / 25%，不是各自最大血量百分比。本次加入完成后地图大小和格子总数保持固定，下一方加入时再次扩图，实际战线使用下述包围场；四参数平面构造仍保留用于已有调用与平面规则检查，不代表当前实战几何。

自动生成的侵蚀孔洞已取消，包括随机腹地占领、孔洞生长及环形接触带。血量优势只推进主分界线；主动占领和技能保护仍可形成独立领地。

## 战线包围与孤岛

实际战场使用带双方开战位置的 DomainTerritoryPartition。接近均势时为轻微弯曲战线，弱方面积比例低于约 30% 后逐渐包卷，至约 20% 完全转成不规则连通孤岛；继续失血缩小，回血逐步撑开。中心保存为双方开战时的位置，不跟随人物移动。没有自动腹地随机孔洞；额外据点仅来自主动占领或保护。

FirstFraction 仍按当前绝对血量比例平滑追赶，每 tick 最多改变 1/contestBoundaryTicks（默认 120）。有符号场通过同一三角形裁剪面积求阈值，保护及占领格纳入面积补偿，固定地必须保留时作为下限。真实格子使用格中心归属，网格在格内连续裁剪，所以离散格数存在微小量化；不会删除地图格子。BoundaryX 只保留名义直线位置供旧平面接口和诊断使用，运行中的曲线归属必须读取 BaseSignedDistance / SignedDistance / IsFirst / OwnsCell。

首方、挑战方的 TerrainGrid、建筑显隐、技能归属、主场减伤与占领侵蚀读取同一分区。DomainTerritoryGeometry 按格三角形裁剪互补地形；公共接触带、双方材质和屏幕边缘读取距离场纹理，不能继续按 x 坐标直线裁剪。边界变化只标记旧／新接缝与归属发生变化的 Section。只读当前格式，不为旧版进行中的对抗额外迁移。

`SectionLayer_DomainContest` 在边界附近读取双方原始地形快照，按连续边界裁剪格子几何，让画面接缝在格子内部平滑移动。自定义地形通过 `DomainWorker.GetTerrainMaterial(terrain)` 提供显示材质；默认使用原版 TerrainGrid 材质，不复制、不释放原版缓存。血海提供自己的动态材质，并在对抗期间将材质 Fullness 保持为 1，血量仅决定分割线位置，不再同时收缩领域内部的血海。血海普通地形层在接缝附近交给通用层绘制，避免重复覆盖。

`DomainTerrainSnapshot` 保存原始 TerrainDef 列表和中心平移量，尺寸不同时居中映射，超出原图范围的格子用原图边缘补齐，不缩放。已有双地图合并时额外保留共享来源上的相对偏移。专用战场采用中性父对象与生成配置，每次租用重新铺设双方内容；区域不拥有独立天气或温度。独立领域回收仍恢复自己的模板。

每个实例的 DomainLayout 保存其模板建筑。先收起双方越界建筑，再恢复归本方的建筑，完整占地必须归属一致；建筑在 ThingOwner 中保留原对象并深度保存，损坏和品质不因战线往返重置。现有物件阻挡时等待，不删除阻挡物。合并两张已有地图前先收起双方模板建筑，布局转交新实例后按原坐标显示，避免把模板建筑当战利品搬到附近。已登记的动态技能建筑纳入实例布局及清理，未登记建筑和战利品仍走原安全迁移；特殊初始组件通过 CaptureStructure 扩展，见领域系统参考。

边界更新按实际 Section 合并脏标记，不逐个给边界整带的格子重复登记。地形切换和恢复跳过已经相同的 TerrainDef；初始化仍整体标记一次地形，确保双方同地形时也创建接缝层。接缝只重建曲线附近的裁剪网格，领域的通用平面网格继续复用；距离场纹理按分区 Revision 更新，材质释放时同时释放纹理。

## 领地战斗规则

### 领域主主动占领

DomainOccupation 为双方分别保存连续敌区停留时间。双方对抗就绪、入场解锁且规则未暂停时，只统计生成在共同地图内、存活且未倒地的本方领域主；以 OwnsCell 查询其脚下实际归属。连续 180 游戏 tick 触发，敌区内移动可继续计时，回到本方、离图、失去条件或对抗结束则清零。每个 game tick 只推进一次，未观察的时间跳跃不补算，暂停不推进。

到时双方先按同一份归属状态判断资格，再调用 Partition.Capture 处理当前位置半径 2 格的原版 GenRadial 范围。保护格跳过；双方圆形范围交叠时较近的一方获得格子，等距保留原归属。成功夺得至少一个敌方格子才恢复 300 本方领域血量，不突破最大值；没有改为给人物治疗。自然消耗仍正常结算。占领生效期间原地不重复回血；失守后重新满足连续 3 秒敌区停留可再次占领回血。

firstClaims / secondClaims 保存双方占领格，独立于临时保护。OverrideAt 将保护优先叠加到占领上，SignedDistance / OwnsCell / DomainAt、实际地形、布局、血海技能倍率、30% 主场减伤、整格网格及基础屏幕边缘都使用这个最终归属。占领格计入己方配额并补偿主线；固定格大于血量份额时成为最小面积。本方退出后同时清除计时与占领，剩余方全图接管。

占领格持续位于敌方主分界一侧时，每格独立累计有效对抗 tick，默认 600 tick（10 游戏秒）后解除占领覆盖。`DomainDef.contestClaimErosionTicks` 配置本方占领地的时限，必须为正。归属检测忽略占领覆盖，避免占领地永远自证属于己方；己方主线到达或保护生效即重置该格暴露计时。入场锁与暂停规则不累计，重复同 tick 不累计，保存暴露进度和去重 tick。失守同步更新地形、建筑、技能和屏幕边缘，失守本身不回血。对方重新占领会清除原计时。取消了永久保留占领的旧规则，不做旧存档迁移。

接触带的通用平面和边缘网格通过 RebuildUnclaimed 排除全部固定归属格，包含保护与主动占领，不再在这些格子内绘制另一方接触材质。只在分区版本变化时更新复用网格，随对抗释放；普通无固定格仍使用原平面路径。原展开与融合动画不改动。

共同战场负责唯一的自然消耗结算。DomainDef.contestHealthLossPerSecond 默认 0.005；N 个活动领域时，每方每游戏秒损耗自身最大血量×0.005×(N−1)，八方为 3.5%。各活动方 Ready、入场解锁且 Worker 未暂停生命周期时，同一 tick 各扣 1/60 秒的量；结算 tick 随存档保存，重复刷新分区不重复扣血。已退出或崩塌者不计数，少于两方不扣；暂停没有自然 tick。自然损耗不记录受击反冲，也不经人物减伤；同 tick 耗尽的各方均触发崩塌。

主场减伤固定为 30%，仅适用于领域施术者在其本方真实领地内受到的伤害。先乘 0.7，再进入共享血量吸收，溢出继续伤人；建筑、其他参与者和直接技能消耗不减伤。主动占领与保护区也使用 OwnsCell 判定。

框架不禁止跨领地施法，也不统一削弱 Ability。血海在自己的模组中移除触手、潮汐与穿行的敌区硬限制，由 DefModExtension_BloodSeaDomainRules.enemyTerritorySkillFactor 配置倍率，当前为 0.7。潮汐按命中位置降低伤害和击退；建筑击穿阈值同步使用实际削弱后的伤害。触手在目标位置计算初始控制时长，每次持续伤害重新查询所在地强度；越线不会删除触手。穿行按目的地强度延长耗时，重载不重复延长。其他领域按自身技能需求使用归属查询，不增加两两配对规则。

MapComponent_Domain.ProtectTerritory(cells, durationTicks, source) 保护当前属于自己的非空格子集合并返回编号；RemoveTerritoryProtection(id) 仅能移除本方保护。可在同一格叠加同方多个来源，单个到期不影响其他来源。保护绑定的来源 Thing 被毁、计时结束或本方领域关闭时移除。保护状态、来源引用和时限均保存；全图领地归属、地形、建筑和基础屏幕边缘读取相同保护结果。

保护格优先于主线及占领，其面积计入己方配额并从其余可争夺区域补偿。如果保护面积超过当前血量应得面积，以保护面积为下限，不强行删除保护格。保护结束后恢复血量分区或仍保留的占领归属。保护边缘沿实际格子边界绘制，不伪装成只影响画面的区域。

MapComponent_Domain.RegisterStructure(building, parkOnTerritoryLoss=true) 登记运行中技能生成的建筑；登记时建筑须已生成在本方完整占地内，同一建筑不能重复登记。true 沿用模板建筑的失地托管与夺回恢复；false 保留失地处的实际建筑，停用、夺取等效果由其自身组件处理。两种都会保存原对象和损伤、随本方 Dissolved 清理。未登记的普通物件不自动收编。RestoreHealth 已可供回血技能调用，不额外维护第二份领域生命值；本次只提供新技能接入口，没有增加未指定的技能文案或技能 Def。

## Worker 与引用入口

- `SupportsContests` 默认 false，基础 DomainWorker_Visual 已启用。自定义 Worker 必须按区域约束玩法后才能启用。
- `DomainAt(cell)` / `FindDomainFor(caster)` / `HasActiveDomain` / `HasOtherActiveDomain` / `GetActiveWorker<T>()` 均通过 Battlefield 查询共同战场，任一方调用结果一致；主线、占领、保护和幸存方接管均遵循此规则。`FindDomainFor(null)` 返回宿主实例。
- `OwnsCell(cell)` 判断是否属于调用方，`GetWorker<T>()` 仅返回调用实例的 Worker。直接从 Map 取得的组件是第一实例，寻找第二方应先调用 `FindDomainFor(caster)`。
- `CQFDomainRuntime.GetInstances(definition)` 返回实例，包括第二方；`GetMaps(definition)` 也包含承载第二方的地图。
- `PreparingContest()` 释放飞行载具等特殊容器；`ContestStarted()` 重建 Lord 或缓存；`TerritoryChanged()` 通知边界改变。技能范围、命中和区域效果须自行查询 OwnsCell。
- 外部建筑通过 `BindDomain(instance)` 保存地图与施术者身份；保护 Hediff 通过自身 Pawn 查找实例，不能只凭地图绑定第一方。

寂屋邪祭本机 1.7 已接入血海反展开、重叠合并、区域地形材质、技能查找、触手/潮汐范围、飞行载具释放和复活记录。保留该仓库原有未提交修改，未覆盖 1.6 DLL。

## 退出与保存

主动取消与崩塌采用相同规则：只要对方仍活动，本方人物与尸体被困在共同地图。退出先调用 PrepareReturn；1.7 基础和血海的可见退出沿用各自全屏特效，完成遮盖后才由 HoldInBattlefield 结束本方规则，移除保护、血条、载体、布局及屏幕边缘，保留原位置、施术者与来源记录并标记 Trapped。DomainWorker.Dissolved 撤销临时能力与持续规则，不调用表示实际离图的 Returned。幸存领域在遮盖下接管全部真实地形与布局，同一转场绑定到原共同地图，确认新地形已绘制后揭幕；暂停时也能完整交接。不可见退出直接完成滞留，不等待屏幕效果。

最后一个领域结束时，先验证双方返程目的地，再沿最后一方的遮盖屏障分别返回双方参与者和尸体。滞留方使用自己的 sourceMap、sourceOrigin 和原参与者记录，调用自己的 PawnLeaving / Returned；松散物品最后带回。全部结束后才清理 Lord、布局并休眠；专用战场下次租用重新铺地，独立地图回收恢复模板。双方同时取消或同时耗尽也沿同一流程处理，不能让滞留记录被空闲地图复用。

深度保存第二实例、Trapped 状态与参与者来源、两份地形快照、双方布局与托管建筑、当前连续比例、左右方向及冲击状态，载体另存施术者引用。读取时验证分区尺寸、比例及实例一致性，并重新绑定布局所有者，不读取旧 firstCells 配额格式、不做旧存档迁移。

MapComponent_Domain 已密封。不要新增继承它的具体 DomainInstance 类型：原版 Map.FillComponents 会自动实例化所有非抽象地图组件，并可能让派生组件取代宿主，进而漏存挑战方。第二方的构造参数标记其独立身份，Scribe_Deep 读取时同样传 map 与 true；宿主始终保存 challenger 和 contest，第二方不递归保存战场。
