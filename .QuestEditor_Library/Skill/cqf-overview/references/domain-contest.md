# CQF 领域对抗

本实现纳入 CQF 4.0 的 RimWorld 1.7 运行包。双方共享一个物理 Map，第一方由原版登记的 MapComponent_Domain 持有；第二方通过 MapComponent_Domain(map, true) 显式构造并独立保存，不加入原版 Map.components，由共同战场转发 Tick / Update / Draw / OnGUI / FinalizeInit。双方各有 Worker、施术者、参与者、血量、来源和载体；地图仍由唯一 GameComponent_MapManager 托管。血海专有适配属于独立的寂屋邪祭仓库，不随 CQF 仓库一同发布。

## 展开与合并入口

- `CQFDomainRuntime.EnterOrContest(definition, caster, targets)`：普通地图上获取领域并进入；已有领域内由另一施术者展开时创建第二实例，转移参与者记录，保留当前人物位置和原返回位置。挑战者直接读取预生成模板，不唤醒第二张地图。
- 同一来源地图的两个活动载体，在距离不超过双方半径之和时自动合并战场。人物、物品、建筑和植物迁入共同地图；建筑/植物按原朝向寻找不会覆盖现有物件的完整占地，实际生成使用同一朝向，无法安全落地则报错并尝试恢复已移动物件的位置及朝向。每次生成后确认目标地图与生成状态。空出的地图休眠；接管实例后的异常仍不具备完整事务回滚。
- 1.7 同图展开范围重叠时，由 `DomainOpening_Fusion` 配对两个活动展开物件。原地图共用 DomainFusionVisuals 的平面侵蚀、接触波纹和接缝，两个原罩子保留，在交叠区域应用同一侵蚀场；单独展开保持。双方展开完成且接触至少一秒后共用一次 DomainFusionTransition，完整遮盖后直接进入一张对抗地图。外部建筑继续共享融合绘制，不能停留为两个闭合罩子独立叠放。基础/基础、基础/血海、血海/基础、血海/血海均接入。
- 另一方可以在第一方单独转场尚未切图时加入；旧转场先脱离原展开物件再释放，避免 Dispose 销毁仍在施法的对象。取消一方会解除配对，存活方继续独立展开；远距离展开仍各自进入。血海捕获列表排除其他正在施法的领域施术者。
- 只在进入、展开注册、读档等状态变化后排队检测，不空闲扫描休眠池。无关转场与退出串行播放，避免互相释放资源。失败地图对本轮不反复自动重试，新一轮展开会清除失败记录。
- 首版每场最多两个实例。败方退出后胜方继续维持，全部结束并回收地图后开始下一场；本场不再加入第三个实例。

preload=true 的领域在准备阶段保留两张原类型地图，缓存原始 DomainMapTemplate（地形与建筑蓝图）并深度保存。反展开直接读取缓存，不再 Acquire / Activate 一张临时模板地图；同步展开只唤醒宿主战场，第二方也读取缓存。同类领域不再因唯一模板被自己占用而现场生成地图。缓存缺失或池容量耗尽的回退仍会生成地图，不能宣称无限次并发都不加载；正常两方对抗由预生成与缓存覆盖。

`DomainDef.surface` 可省略。纯建筑与地形领域使用原场景，公共绘制器只提供接触与转场遮盖，不创建整图颜色面。通用展开的 SupportsFusion 与 surface 解耦；自定义展开器仍需明确启用融合，Worker 仍需明确 SupportsContests。新增领域只提供自身定义、地图生成、规则和可选材质，不增加两两配对实现。

## 占地

`DomainTerritoryPartition.CalculateFraction` 使用当前绝对血量，第一方目标总面积比例为 `H1 / (H1 + H2)`，双方归零时为零。3000 对 1000 对应 75% / 25%，不是各自最大血量百分比。完整地图大小和格子总数固定。无孔洞时由一条贯穿地图的直线分区；第一方在左时 `BoundaryX = 地图宽度 × 比例`，在右时反向。

1.7 在优势方总面积比例超过 70% 时逐渐形成三处侵蚀孔洞，到 90% 时达到最大侵蚀强度。DomainInvasion 保存种子、侵入方与生长强度，确定性重建位置、尺寸与各不相同的凹凸轮廓；位置随领地比例连续调整，优势减弱时逐渐闭合，优势反转先关闭旧洞再形成另一方孔洞。小于 16 格宽或高的地图不形成孔洞。洞内是真实的优势方领地，地形切换、建筑收起/恢复、技能和持续效果均查询同一归属，不能只做 Shader 假象。

孔洞面积计入优势方的血量配额。分区根据同一 48 段径向轮廓与矩形裁剪后的实际面积求解主线位置，避免在原配额外凭空增加面积。`FirstFraction` 是平滑中的总面积比例，`BoundaryX` 是补偿后的主线；`FirstCells` 是包含孔洞的实际格子中心计数，`FirstColumns` 仅描述主矩形。实际格子数存在中心采样量化，连续面积按比例求解。`contestBoundaryTicks` 默认 120，每 tick 总面积比例最多改变 1/120；孔洞同步平滑生长。不移动人物，也不减少地图格子。

分区复用格子归属缓存并记录 ChangedCells，只修改真正换方的地形。主线和旧/新孔洞包围盒按 Section 合并刷新；孔洞生长未跨过格子中心时仍更新曲线网格。DomainTerritoryGeometry 在曲线附近以四分之一格三角裁剪双方材质，同一网格构造器也为非专用地形的 surface 提供带孔区域网格。无 surface 的领域直接绘制对应真实地形，不需要新增领域 Shader。原地建筑和展开/融合动画保持原有入口。

主线两侧各 1.6 格为动态接触带。有 surface 时局部重叠双方真实材质，通过共享的波动遮罩侵蚀；已通过真实地形绘制 surface 的 Worker 也只在接触带补绘，不重复覆盖整图。孔洞增加环形接触带，与直线共用 CQF_DomainContestFront。`contestColor` 提供双方接触颜色，推进差值产生压力，扣血记录有方向且逐渐衰减的冲击。表现沿游戏 tick 推进，暂停时停止；局部装饰波动不改变规则，Shader 不决定格子归属。RSH 的 1.7 隐藏领域地形覆盖 edgeType=Hard，避免原版邻格渐变使用未初始化图形产生红色方块，普通血池仍保持原有边缘。

`SectionLayer_DomainContest` 在边界附近读取双方原始地形快照，按连续边界裁剪格子几何，让画面接缝在格子内部平滑移动。自定义地形通过 `DomainWorker.GetTerrainMaterial(terrain)` 提供显示材质；默认使用原版 TerrainGrid 材质，不复制、不释放原版缓存。血海提供自己的动态材质，并在对抗期间将材质 Fullness 保持为 1，血量仅决定分割线位置，不再同时收缩领域内部的血海。血海普通地形层在接缝附近交给通用层绘制，避免重复覆盖。

`DomainTerrainSnapshot` 保存原始 TerrainDef 列表，尺寸不同时比例采样。最后回收时恢复宿主原地形，避免下一次唤醒保留混合内容。共享地图沿用宿主环境和父对象，区域不拥有独立天气或温度。

每个实例的 DomainLayout 保存其模板建筑。先收起双方越界建筑，再恢复归本方的建筑，完整占地必须归属一致；建筑在 ThingOwner 中保留原对象并深度保存，损坏和品质不因战线往返重置。现有物件阻挡时等待，不删除阻挡物。合并两张已有地图前先收起双方模板建筑，布局转交新实例后按原坐标显示，避免把模板建筑当战利品搬到附近。已登记的动态技能建筑纳入实例布局及清理，未登记建筑和战利品仍走原安全迁移；特殊初始组件通过 CaptureStructure 扩展，见领域系统参考。

边界更新按实际 Section 合并脏标记，不逐个给边界整带的格子重复登记。地形切换和恢复跳过已经相同的 TerrainDef；初始化仍整体标记一次地形，确保双方同地形时也创建接缝层。矩形区域及分割线复用固定平面网格，只改绘制矩阵，不随边界推进重建三张网格。

## 领地战斗规则

### 领域主主动占领

DomainOccupation 为双方分别保存连续敌区停留时间。双方对抗就绪、入场解锁且规则未暂停时，只统计生成在共同地图内、存活且未倒地的本方领域主；以 OwnsCell 查询其脚下实际归属。连续 180 游戏 tick 触发，敌区内移动可继续计时，回到本方、离图、失去条件或对抗结束则清零。每个 game tick 只推进一次，未观察的时间跳跃不补算，暂停不推进。

到时双方先按同一份归属状态判断资格，再调用 Partition.Capture 处理当前位置半径 2 格的原版 GenRadial 范围。保护格跳过；双方圆形范围交叠时较近的一方获得格子，等距保留原归属。成功夺得至少一个敌方格子才恢复 300 本方领域血量，不突破最大值；没有改为给人物治疗。自然消耗仍正常结算。转化后所在位置归己方，原地不能每 3 秒刷回血，需要重新进入敌区。

firstClaims / secondClaims 保存双方占领格，独立于临时保护。OverrideAt 将保护优先叠加到占领上，SignedDistance / OwnsCell / DomainAt、实际地形、布局、血海技能倍率、30% 主场减伤、整格网格及基础屏幕边缘都使用这个最终归属。占领格计入己方配额并补偿主线；固定格大于血量份额时成为最小面积。占领只被对方占领或本方结束清除，不被日常主线移动抹去；本方退出后同时清除计时与占领，剩余方全图接管。

接触带的通用平面和边缘网格通过 RebuildUnclaimed 排除全部固定归属格，包含保护与主动占领，不再在这些格子内绘制另一方接触材质。只在分区版本变化时更新复用网格，随对抗释放；普通无固定格仍使用原平面路径。原展开与融合动画不改动。

共同战场负责唯一的自然消耗结算。DomainDef.contestHealthLossPerSecond 默认 0.005，含义为每游戏秒损耗自身最大血量的比例。双方 Ready、入场均已解锁且 Worker 未暂停生命周期时，同一 tick 各扣 1/60 秒的量；结算 tick 随存档保存，重复刷新分区不重复扣血。一方结束或入场未完成时不扣，暂停游戏没有自然 tick。自然损耗不记录受击反冲，也不经人物减伤；同 tick 双方耗尽都触发各自崩塌，不先把整图判给顺序靠前的一方。

主场减伤固定为 30%，仅适用于领域施术者在其本方真实领地内受到的伤害。先乘 0.7，再进入共享血量吸收，溢出继续伤人；建筑、其他参与者和直接技能消耗不减伤。侵蚀孔洞与保护区也使用 OwnsCell 判定。

框架不禁止跨领地施法，也不统一削弱 Ability。血海在自己的模组中移除触手、潮汐与穿行的敌区硬限制，由 DefModExtension_BloodSeaDomainRules.enemyTerritorySkillFactor 配置倍率，当前为 0.7。潮汐按命中位置降低伤害和击退；建筑击穿阈值同步使用实际削弱后的伤害。触手在目标位置计算初始控制时长，每次持续伤害重新查询所在地强度；越线不会删除触手。穿行按目的地强度延长耗时，重载不重复延长。其他领域按自身技能需求使用归属查询，不增加两两配对规则。

MapComponent_Domain.ProtectTerritory(cells, durationTicks, source) 保护当前属于自己的非空格子集合并返回编号；RemoveTerritoryProtection(id) 仅能移除本方保护。可在同一格叠加同方多个来源，单个到期不影响其他来源。保护绑定的来源 Thing 被毁、计时结束或本方领域关闭时移除。保护状态、来源引用和时限均保存；全图领地归属、地形、建筑和基础屏幕边缘读取相同保护结果。

保护格优先于主线及侵蚀轮廓，其面积计入己方配额并从其余可争夺区域补偿。如果保护面积超过当前血量应得面积，以保护面积为下限，不强行删除保护格。保护结束后恢复血量分区。保护边缘沿实际格子边界绘制，不伪装成只影响画面的区域。

MapComponent_Domain.RegisterStructure(building, parkOnTerritoryLoss=true) 登记运行中技能生成的建筑；登记时建筑须已生成在本方完整占地内，同一建筑不能重复登记。true 沿用模板建筑的失地托管与夺回恢复；false 保留失地处的实际建筑，停用、夺取等效果由其自身组件处理。两种都会保存原对象和损伤、随本方 Dissolved 清理。未登记的普通物件不自动收编。RestoreHealth 已可供回血技能调用，不额外维护第二份领域生命值；本次只提供新技能接入口，没有增加未指定的技能文案或技能 Def。

## Worker 与引用入口

- `SupportsContests` 默认 false，基础 DomainWorker_Visual 已启用。自定义 Worker 必须按区域约束玩法后才能启用。
- `DomainAt(cell)` / `FindDomainFor(caster)` / `HasActiveDomain` / `HasOtherActiveDomain` / `GetActiveWorker<T>()` 均通过 Battlefield 查询共同战场，任一方调用结果一致；主线、孔洞、占领、保护和幸存方接管均遵循此规则。`FindDomainFor(null)` 返回宿主实例。
- `OwnsCell(cell)` 判断是否属于调用方，`GetWorker<T>()` 仅返回调用实例的 Worker。直接从 Map 取得的组件是第一实例，寻找第二方应先调用 `FindDomainFor(caster)`。
- `CQFDomainRuntime.GetInstances(definition)` 返回实例，包括第二方；`GetMaps(definition)` 也包含承载第二方的地图。
- `PreparingContest()` 释放飞行载具等特殊容器；`ContestStarted()` 重建 Lord 或缓存；`TerritoryChanged()` 通知边界改变。技能范围、命中和区域效果须自行查询 OwnsCell。
- 外部建筑通过 `BindDomain(instance)` 保存地图与施术者身份；保护 Hediff 通过自身 Pawn 查找实例，不能只凭地图绑定第一方。

寂屋邪祭本机 1.7 已接入血海反展开、重叠合并、区域地形材质、技能查找、触手/潮汐范围、飞行载具释放和复活记录。保留该仓库原有未提交修改，未覆盖 1.6 DLL。

## 退出与保存

主动取消与崩塌采用相同规则：只要对方仍活动，本方人物与尸体被困在共同地图。HoldInBattlefield 结束本方规则，移除保护、血条、载体、布局及屏幕边缘；保留原位置、施术者与来源记录，标记 Trapped，不播放返回转场、不调用 Returned。DomainWorker.Dissolved 用于撤销临时能力与持续规则，血海已接入。幸存领域立即接管全部真实地形与布局，暂停时也不留半张已失效地形。

最后一个领域结束时，先验证双方返程目的地，再沿最后一方的遮盖屏障分别返回双方参与者和尸体。滞留方使用自己的 sourceMap、sourceOrigin 和原参与者记录，调用自己的 PawnLeaving / Returned；松散物品最后带回。全部结束后才清理 Lord、恢复模板并休眠。双方同时取消或同时耗尽也沿同一流程处理，不能让滞留记录被空闲地图复用。

深度保存第二实例、Trapped 状态与参与者来源、两份地形快照、双方布局与托管建筑、当前连续比例、左右方向及冲击状态，载体另存施术者引用。读取时验证分区尺寸、比例及实例一致性，并重新绑定布局所有者，不读取旧 firstCells 配额格式、不做旧存档迁移。

MapComponent_Domain 已密封。不要新增继承它的具体 DomainInstance 类型：原版 Map.FillComponents 会自动实例化所有非抽象地图组件，并可能让派生组件取代宿主，进而漏存挑战方。第二方的构造参数标记其独立身份，Scribe_Deep 读取时同样传 map 与 true；宿主始终保存 challenger 和 contest，第二方不递归保存战场。
