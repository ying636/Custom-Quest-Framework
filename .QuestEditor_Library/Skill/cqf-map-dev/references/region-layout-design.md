# CQF 区域标记与布局生成方案

2026-10-29 用户确认实施。先保存方案，再实现与验证。本文记录目标与验收条件，不表示以下能力已经实现。

本轮已落地区域标记、保护、六类布局和既有生成流程接入，实际接口与当前限制见 [区域布局用法](region-layout-usage.md)。道路模板拼装及更细的地形筛选仍为后续扩展；当前道路使用指定地形。

## 目标

作者在地图上绘制区域，赋予稳定 Key、名称和 tag；生成脚本查询区域的实际格子、边界和连接点，以区域为基准选择位置，再从现有地图部件中按 tag 和权重抽取并生成。典型流程是标记主城，保留主城原有内容，在城外生成几个小聚落，并连接主城与聚落。

区域身份与保护规则分别配置。标记为主城表示该区域可供脚本引用；启用保留才限制布局修改。任意区域都可用于内部、外部、周边或指定方向的生成，不把主城等具体角色写死进框架。

## 区域数据与编辑

- 区域有唯一 Key、作者名称、多个 tag、实际格子集合、可选连接点及保护选项。
- 编辑器支持创建、选择、重命名、删除区域，以及矩形绘制、涂画、擦除、显示边界和设置连接点。
- Key 精确选择一个区域；tag 可选择多个区域，脚本明确选择逐区域执行或要求唯一，缺失和歧义均报错。
- 区域可以重叠；保护按所有保护范围的并集执行。多格建筑与保留区相交时保护整个建筑。
- 模板保存局部坐标；生成时转换为实际地图坐标。复制、旋转、平移、导出、载入均携带区域和连接点。
- 重复放置同一部件使用独立实例身份，避免内部同名区域互相覆盖。生成结果可以登记为新区域，供后续脚本引用。
- 在现有 MapComponent_CustomMapData 中管理地图上的区域实例，保留现有事件区域行为，不将会在触发后删除的 CQFEventArea 作为永久布局标记。

## 围绕主城生成聚落

1. 手工制作主城，绘制主城区域并指定 Key 或 tag，按需启用保留。
2. 在城门位置标记连接点与朝向。
3. 布局步骤按 Key 或 tag 查询主城；配置聚落数量、距主城边界的范围、聚落间距、允许方向和候选部件 tag。
4. 以主城实际边界计算可用范围，避免用中心距离误判大型或不规则城市。
5. 先筛选可放置的部件和朝向，再加权抽取；完整占地不得与主城、其他保护区、已占用区域或地图外部相交。
6. 规划连接主城连接点与聚落入口的道路，校验必需通路。
7. 完整规划通过后才执行生成，成功放置的聚落登记独立区域；后续可围绕聚落继续布置农田、营地等。

## 首批布局

| 布局 | 空间规则 |
|---|---|
| 城市街区 | 主干道与支路划分街区，建筑沿街，入口朝路，按角色 tag 分配地块 |
| 村落聚落 | 围绕指定区域或中心布置建筑，小路连通，支持主城外围卫星聚落 |
| 荒野散布 | 保留自然底图，探索点保持最小距离，按数量、tag 和权重抽取 |
| 荒野群落 | 选择群落中心，围绕各中心布置同组部件，群落之间保留间隔 |
| 废墟城区 | 城市道路骨架配合完整、残破和空置比例，使用相应部件 tag |
| 围合据点 | 边界、入口、内部道路和中心区域分层规划，围墙、转角、门楼使用对应部件 |

算法独立文件。布局 Def 保存算法类型、参数和部件规则；CustomMapStep_Layout 作为现有生成步骤的扩展入口。道路默认按配置地形绘制，可配置道路部件。具体部件资源由已有或用户提供的部件库供给，不凭空生成剧情、人物文案或建筑模板。

## 筛选与生成约束

- 部件必须是可用于拼装的 CustomMapDataDef，复用现有 tags、权重、生成上限与 GenerateByCore。
- 新布局支持必含、任选与排除 tag，显式部件候选，以及角色数量、尺寸、朝向、间距和地形条件。
- 原有 CustomMapGenerationSet 的选择语义不变，增强筛选只用于新布局。
- 部件入口优先使用现有区域核心和连接信息；新增的区域连接点供道路与范围脚本引用。
- 同一输入与种子产生可复现规划，预览不修改地图或消耗实际生成计数。
- 关键部件缺失、无法满足数量、道路不通和不支持的写入步骤须明确报错。可选项只有显式允许才可跳过，并保留结果说明。
- 空间冲突按完整部件和完整建筑占地判断，不能裁掉半栋建筑继续生成。

## 原有地图与保护

原有地图模板先生成手工底图，再执行布局扩展。保留区在扩展开始前生效，不阻止底图中的主城或入口自身生成。在当前地图追加布局时直接使用现有地图，不重建底图。

原有禁止生成、禁止摧毁各自保留含义，新布局分别尊重。完整保留区额外限制清场、建筑与物品生成、地形、屋顶和道路修改。保护范围优先于布局参数，嵌套区域核心继承同一限制，子调用只能收紧而不能扩大允许范围。

保护信息通过本次生成上下文传递，不写进共享 Def 的运行缓存。直接操作地图的第三方 GenStep 或自定义动作只有接入范围校验才支持严格保护；不支持者在生成前明确拒绝，不能宣称任意脚本自动受保护。保护针对布局生成操作，不禁止玩家正常游玩时修改地图。

## 接入边界

- 复用 CustomMapDataDef、preCustomSteps/customSteps、CustomMapGenerationSet、ZoneCore 和 GenerateByCore。
- 保持既有任务、人物、交互、数据库和任务标签传递，新增布局不替换地图生命周期。
- 未使用新字段和新布局步骤的地图继续执行原有逻辑。
- 区域新增到模板序列化、坐标变换和当前格式存档，不增加旧存档迁移。
- 不新增 Utility 类、不增加代码注释、类按既有文件边界组织，新增 defName 使用 CQF_ 前缀。
- DLL 显示文本使用 Key 与双语资源。缺失文本使用稳定 Key 同名占位，登记 CSV 与 Excel 审核表；不增加英文 DefInjected。

## 实施顺序与验收

1. 区域数据、地图登记、坐标变换、保存载入及编辑器绘制。
2. 范围查询、保护上下文、候选筛选和预览。
3. 主城外围聚落、城市街区与荒野散布，打通既有生成入口。
4. 群落、废墟、围合据点与道路连接。
5. 离线规则测试、实际程序集构建、独立游戏验证，更新技能使用说明与文本审核表。

验收涵盖区域复制旋转与重复实例、精确边界距离、重叠区域、缺失或重复引用、不同地图和部件尺寸、稳定种子、数量上限、嵌套生成保护、入口可达性、地图与部件保存载入、旧配置行为，以及生成前后保留区建筑、物品、地形、屋顶保持一致。明确区分离线规则通过、编译通过和游戏内验证。
