# 复合地图

RimWorld 1.7 的 `CQFCompositeMapDef` 负责生成一组独立的 CQF 子地图。成员沿用 `CustomMapDataDef`，同一定义可以生成多组独立实例。

- `regions` 的成员需要唯一 `id`、`map` 和 `position`。`position` 是小地图网格坐标，正 X 向右，正 Z 向上。
- `entry` 指定默认入口成员，`entryCell` 是该成员内的进出位置。生成时还要传入来源地图和入口地格，系统会在两端生成出入口物件。
- `edges` 使用 `from`、`to`、`fromEdge`、`toEdge`、`fromStart`、`toStart` 和 `length`。边需相对，两端长度相同。南北边以 X 为区段坐标，东西边以 Z 为区段坐标。玩家控制的殖民者步行到相连的边缘格后自动跨图，并从目标地图对应位置向内一格处出现。
- `portals` 使用 `from`、`to`、`fromCell` 和 `toCell`。可用于楼梯和非物理穿行，默认在两端生成出入口。两类连接的 `twoWay` 均默认为 `true`。选择实体出入口后，使用通行指令并指定殖民者。
- `CQFAction_GenerateCompositeMap` 在一个地格目标上生成定义，其中 `definition` 引用相应 Def。C# 入口为 `GameComponent_MapManager.GenerateCompositeMap`，返回本次实例。来源应为已生成且正在运行的地图。
- 组内查看用右上角小地图。左侧三条杠打开全图，拖动标题可移动小地图，右侧展开或收起小地图。实线表示边缘连接，虚线表示出入口。点击区块切换视角。当前地图用白色描边，有殖民者的后台地图用蓝色，被模块保活的空地图用红色。悬停入口区域可查看入口提示。小地图下方只显示当前区域的殖民者头像，并使用原版殖民者栏的头像框和选中角标。全图按区域显示所有殖民者，空间不足时等比缩小。两处头像均支持单击选中，双击切到人物所在地图并定位。全图中单击其他区域的人物时，先在全图中选中其头像。每组复合地图只在原版顶部殖民者栏保留入口分组。入口休眠时，点击该分组会唤醒并切到入口。
- 自动入场文字默认关闭。添加 `<showEntranceTitle>true</showEntranceTitle>` 后，第一次查看地图时会显示本地化地图名，显示记录随存档保存。放在 `CustomMapDataDef` 上可启用使用该 Def 的地图，放在 `MainMapDef` 上可启用主图，放在 `CQFCompositeMapDef` 上可一次启用所有成员。复合地图只想开启部分成员时，在对应成员使用的 `CustomMapDataDef` 上开启即可。
- `CQFAction_ShowMapTitle` 可主动显示文字，不受自动开关控制。填写 `text` 可显示任意文字或翻译 Key，无需指定地图。留空时显示目标地图名，默认目标键为 `Position`。行为在玩家当前的地图画面显示文字。

- 未显示且无殖民者的成员交由 `GameComponent_MapManager` 在安全更新点休眠。实际进入或查看时唤醒。暂停时仍可切图和休眠，示意图绘制不唤醒任何地图。
- `DestroyCompositeMap` 删除指定实例。存在殖民者或有另一张子地图以其成员作为返回点时会拒绝。生成及移除失败会报告错误。

独立演示 Mod `HaiLuan.CQFLargeCityDemo` 提供 `CQF_CompositeCity`，包含五张 96×96 地表地图和一张 72×72 地下地图。启用演示后，在开发者菜单选择「CQF → 复合地图 → 大城市」，在来源地图上选择空地放置入口。在中央广场的组织演练告示牌上选择「开始组织演练」，仓库小队和地下小队分别通过街区边界和通道到广场换队。

## 由入口创建复合地图

在起始入口的 ThingDef 使用 `QuestEditor_Library.CustomMapEntrance_Composite`。这个入口支持普通地图 Def 和随机地图池。首次生成的地图是入口所管理布局组的首个成员。来源地图已属于某个复合实例时，新组通过来源区域接入该实例。

- 用 ThingDef 的 `ModExtension_CQFCompositeEntrance.layout` 指定布局，默认 `Vertical`。首张地图在原点，纵向布局把新地图放到来源下方，横向布局放到右侧。目标位置已占用时沿另一条轴寻找空位。
- 普通入口生成的地图加入来源地图的布局组。代码也可在建立地图与通路后调用 `RegisterCompositeSubMap(source, destination, position)`。固定复合地图的默认追加布局用 `CQFCompositeMapDef.appendedLayout` 配置。
- 大窗口顶部为总览和各子组提供标签。父图上的米色节点与来源区域相连，点击会打开对应标签。小地图跟随镜头所在的组，米色节点可直接打开大窗口中的目标标签。
- 复合入口位于 CQF 任务地点时，根组的小地图和全图会显示该地点，可从地下点击切回地表。
- 存档保存入口、组、区域和坐标。移除复合入口会回收它管理的地图分支，移除单个区域同步撤销它的登记。有角色、正在通行或其他地图依赖返回点时，回收请求会被拒绝。

## 跨区行动与搬运

CQF 1.7 将地图边缘、复合地图传送点和已配对的子地图楼梯纳入同一个通行图。通道变化时更新缓存。在「命令」中右键「搬入」可选当前可通行的区域。「搬出」按上级区域结算，「搬出到起点」以复合地图的外部入口所在地图为目的地。

职责编辑器可添加「前往目标地图」和「跨地图报信」两个行为节点。「查找方式」选「目标 key」时，从启用的职责数据库读取目标。选「区域 ID」「地图键」或「地图模板 defName」时，从执行者所在实例的地图数据库查找。可选「仅当前布局组」，查询结果必须唯一。已有定义省略 `targetSource` 时，有复合地图键则查询复合地图，留空则读取职责数据库。

固定区域可在 `CQFCompositeMapDef.regions` 的成员上写 `mapKey`，动态生成的地图可在其 `CustomMapDataDef` 上写 `compositeMapKey`。C# 可用 `instance.MapDatabase.Bind(key, map)` 在实例内登记持久别名，用 `Find` 查询。注册和删除区域时会更新数据库，休眠区域也能查到。

「跨地图报信」要求指定援军小队标签。给 B 图允许出战的组织小队添加同名 `groupTags`。报告送达后，系统从这些小队的同阵营可行动成员里选人，并在离开 B 前再次确认小队归属。发现半径、最大援军数、集结时间和冷却由职责节点配置。C# 调用方可用 `RequestCrossMapMove(pawn, source, destination)` 提交普通调动。

小队本沿用 `GroupDataDef`。「地图小队」可以收录当前地图的小队，也可以从小队本添加模板。地图里的 `LordData.groupTemplate` 指向模板，`name` 用于本图的成员归属，`faction`、`metaLordName` 和 `metaLordEvents` 可以覆盖模板对应值。实体生成器可以从小队本添加整队。编辑生成方案时，通过顶部的「生成时加入小队」选择本图已关联小队本的队伍。跨地图报信可以从小队本选择模板上已有的标签。

在「CQF → 组织」中可查看本图及其他楼层的运行组织并编辑规则。规则保存到 `Quests/Organization`，可在「地图小队」中为组织小队选用。用「发送组织信号」作为职责节点的进入行为时，将实体目标设为 Pawn，组织留空会使用发信者的组织。组织事件可限定发出事件的小队，并按小队名称、标签及可选地图标识选择接令小队。小队命令可以运行职责图或调动可行动成员到一个明确的目的地小队。

组织调动使用同一通行图，从普通子地图入口、动态复合地图和固定复合地图的边界或通道选路。独立生成的固定复合地图实例各自登记组织，同名组织可以复用。临时领域由领域机制传送角色，成员在领域内保留组织身份，返回时恢复原组织小队。

活动区域执行实际寻路 Job。离屏跨区由到期队列推进，休眠地图保持暂停。跨区任务保管已离开地图的原 Pawn 或物品堆及其进度，目的地图恢复运行后再交付。真正从休眠地图移交一个实体时，临时绑定地图索引，复用原版脱离流程，在同一次调用内恢复休眠状态和索引。

## 性能与补丁

复合地图的边缘格在生成和读档时建立索引。地图管理器在游戏 Tick 末尾检查有通行格的活跃区域。每个区域按玩家 Pawn 到地图边缘的最短距离安排下次检查，间隔为 1 到 8 Tick，确认殖民者当 Tick 进入通行格后排队跨图。大城市启用区域标题，首次查看各区域时使用该区域的既有译名。原版殖民者栏重建时通过 Harmony 过滤内部区域并加入休眠入口。地图休眠调用 CQF 既有地图管理器。小地图和全图在窗口尺寸变化时重算布局，绘制阶段才提交连线、标签与高光。

同一六区大城市存档，暂停模拟，2560×1600，每个场景采集 170 帧。以下为原版 Frame profiler 中相应方法的每帧平均值。打开全图时，布局一行包括全图和同屏小地图。

| 测量项 | 优化前 CPU | 优化后 CPU | 优化前分配 | 优化后分配 |
| --- | ---: | ---: | ---: | ---: |
| 来源地图画面，后台有殖民者时的复合地图管理 | 18.22 µs | 1.55 µs | 0 B | 0 B |
| 小地图窗口绘制 | 184.05 µs | 75.43 µs | 2,112 B | 288 B |
| 全图打开时的区域布局绘制 | 234.54 µs | 106.56 µs | 3,488 B | 192 B |

优化候选生成整组的三次调用耗时约 0.71–0.76 秒。休眠地图保留地图数据，数量和大小仍影响内存与存档体积。对照用于上述六区场景的主线程开销，整局表现仍取决于同时活跃的地图和对象数量。
